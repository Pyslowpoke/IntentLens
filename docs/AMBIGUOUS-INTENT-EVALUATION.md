# 模糊需求实测评估

日期：2026-09-27。对象：本机正在运行的观意 IntentLens。结论：**基础探索可用，但目前不能把“能生成图”视为“能理解并完成模糊分析任务”。**

## 测试范围与方法

实时 `/model/status` 返回 `provider=rule, ready=false`，未配置模型密钥。本次没有调用 DeepSeek，也不使用模拟模型回答冒充真实模型能力。

使用三组合成 CSV，共 8 个需求；每次创建带 `[意图评估]` 标记的独立项目，经真实 API 导入、生成方案、执行第一个推荐方案、等待独立 Worker 完成并下载 PNG。另测试模糊改图、明确改图和决策建议。未修改用户原项目或意图处理逻辑。首选方案执行结果用于模拟用户直接接受推荐的路径；同时检查全部候选方案能否满足需求。

## 实测结果

| 用户需求 | 实际行为 | 业务评价 |
|---|---|---|
| 帮我看看这份数据 | 提供时间、地区、产品三个销售额汇总方案，无澄清问题 | 可作为探索起点；不是自动得出业务结论 |
| 做个好看的图，适合给老板看 | 与普通探索相同，未询问受众重点或调整报告表达 | 能出图，缺少针对性 |
| 哪里不太对劲？ | 普通销售额汇总，无异常定义、阈值或检测 | 未完成异常识别 |
| 最近是不是不行了？帮我找原因 | 月度汇总，无“最近”的时间范围或原因分析；有不完整月份和非因果提醒 | 有边界提示，但未回答问题 |
| 看看各地区占比 | 候选方案仍全部为求和；没有占比分母，首选仍是时间趋势 | 未满足占比意图 |
| 转化怎么样，哪个平台更好？ | 按日期/平台汇总转化人数，无转化率分母 | 不能按转化率比较平台 |
| 哪些城市渗透率低，应该优先拓展？ | 提示缺少目标医院总体，给出拜访次数汇总作为替代 | 正确提示数据不足；无法完成渗透率决策 |
| Something looks off. What should I focus on? | 英文说明，但方案计算结构与其他销售需求一致 | 语言适配不等于语义理解 |

- 8/8 任务状态为 completed；8/8 PNG 返回 200 且文件签名有效。
- 8/8 首个图表的聚合总数与独立读取源 CSV 后的求和一致。这只验证所执行的求和计算，不代表口径符合意图。
- 6 个销售需求产生的方案计算结构完全一致：排除 goal 和语言化 limitations 后，只有 **1 种方案结构**。
- 8 个需求仅渗透率案例提出 1 个补充问题，其余 7 个没有澄清。该数量不是普适质量评分，但暴露出关键歧义未处理。
- 推荐接口耗时 23.0–90.3 ms，是本地规则速度，不能代表模型响应延迟。
- “更直观一点”改图返回 422，无法解释；“改成蓝色”返回 200 接受任务。
- 决策建议返回 422，要求配置模型密钥；不会冒充真实 AI 决策。

## 口径对照

用原始合成产品 CSV 独立计算 `sum(转化人数) / sum(访问人数)`：网页端 18.08%，移动端 15.73%，桌面端 14.78%。当前生成的是转化人数总和，虽然本例人数排序恰好一致，不能因此认为正确理解了转化率。

地区占比也可以从销售数据计算：华北 27.14%、西南 24.51%、华东 24.29%、华南 24.05%。当前方案没有执行该比例口径。

## 问题根因与优先级

1. **优先补意图识别与口径澄清。** 规则模式主要由字段类型选择分组和最后一个数值字段，销售额有特殊优先级；除渗透率关键词外，需求文本基本不改变计算方案。
2. **增加可操作的澄清过程。** “转化怎么样”需要展示或确认分子、分母；“最近”需要时间窗口；“哪里异常”需要参照和异常标准。现在 questions 只是展示文字，没有结构化回答与确认流程。
3. **将探索和结论分开。** 可以先提供概览，但必须标明“当前仅做探索，尚未回答原因/异常/策略问题”。不能仅凭任务 completed 宣称需求已完成。
4. **再评估真实 DeepSeek。** 当前模型分支有结构校验，但结构合法并不证明语义正确。接入真实密钥后应复跑这组需求，核查澄清、指标选择、证据、错误恢复及稳定性；本次无法据此判断模型实际表现。
