# Execution and data boundary

- Single-user, local/self-hosted product. No authentication or public multi-tenant security claim. Bind to loopback.
- Model configuration and database URLs are server-only, loaded from process variables or root `.env`; legacy `.local/model.json` is also supported. These local files are excluded from Git and Docker build contexts. The worker only loads resource/data settings from `.env` and removes inherited credential environment variables; its computation children receive an explicit environment allowlist. Compose additionally disables worker networking, drops capabilities and limits CPU/memory/processes. Native Windows development mode is **not** an OS sandbox.
- Only validated AnalysisPlan operations run. Arbitrary Python, eval/exec, model JavaScript and user formatter callbacks are disabled. ECharts options are generated by application code and rendered with a bundled script. Preview HTML is sandboxed in the browser and has restrictive CSP.
- Original files and immutable snapshots remain in local data/. Formula caches are read; macros are not run. Missing formulas, invalid types and size limits are reported. The default reproduction package includes a hash reference, plans and code, not data rows or raw files.
- Models receive column metadata, null/unique counts and numeric/date ranges. They do not receive raw rows by default. Metadata can itself be sensitive. Self-hosting the application does not prevent configured external models receiving these summaries.
- SQLite paths are server allowlisted and opened mode=ro with VM authorizer, query_only and progress timeout. PostgreSQL and MySQL require restricted accounts and read-only transactions, statement timeouts and bounded result collection. SQL AST checks supplement these boundaries, not replace them.
- Database administrative fixtures are synthetic-only and bind loopback. Never reuse fixture passwords or expose test services publicly.

Outstanding hardening: native process-tree resource enforcement; formal tenant isolation (out of V1 scope); malformed workbook decompression limits before openpyxl; private filesystem sharing policies on multiuser hosts. Do not expose this development build to untrusted networks.
